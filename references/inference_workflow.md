# 单轮推演工作表

只使用当前 `reasoning_packet.json`。先检查 `run_id`、`missing` 与用户确认的规则；`missing` 非空时停止定向投票。`evidence_gaps` 是待判断影响的事项，不等于必定无法预测。

1. **技能还原**：读取十名式神每张技能卡的基础文案、按等级顺序叠加全部升级文案，并读取本地导入的状态词释义。后级数值覆盖前级同一效果；不要直接把 `base_cost_api` 当成满级最终鬼火消耗。
2. **先机与行动**：列出开局自动效果、行动条变化、额外回合。`speed_priority_before_action_bar_changes` 只是静态面板速度顺序；确认先机后才能写首轮实际顺序。同速保留顺序分支。
3. **逐方鬼火账**：红蓝初始各 4 火。每次普通回合和技能使用记录本方当前火、支付和有证据的回复。每轮五次普通回合后的回火依次 3、4、5，精确结算相位不明时分支；不可提前使用尚未结算的火。额外回合、反击是否计数按已确认机制处理，未知时分支。
4. **AI 选技能和目标**：按特殊例外、已接受的社区 AI 表、基线假设的顺序。技能可用性还受鬼火与状态约束。随机目标、未覆盖目标规则和并列目标都产生分支；不替自动战斗选择最优对手。攻击与辅助目标可为己方，不能把所有技能目标都当敌方。
5. **每一关键行动的效果**：将多段伤害、保护次数、控制命中与抵抗、御魂逐次触发、死亡触发、反击/追击及行动条变化按文案结算。无法从资料得到精确伤害或触发率时，用导致不同存活状态的条件分支表示，避免捏造数值。
6. **比较分支**：找出决定谁先失去核心单位、谁可持续行动、谁能解除控制或恢复的最小转折集。多个合理分支若同向，可给方向；关键分支反向且无权重证据时弃权。票数不是胜率，历史测试用例的阵容或结果不得代入新一轮。

多模型聚合先看有效票据与证据缺口，再看按模型标识合并后的票数。不要给主模型预设较高权重，也不要把同名模型的多次运行当成多份证据；不同标识也可能有共同偏差。至少四个不同标识、胜方获得全部标识三分之二和定向标识四分之三支持，且 `evidence_gaps` 均已记录为不影响胜负时才自动给方向。其他情况输出 `undecided` 和原因；门槛未经历史对局校准，票数不等于胜率，程序也无法证明推演语义正确。

定向票必须附 `key_actions`。每条只写真正决定结果的一步，包含角色、技能 ID、目标、该步鬼火四个数、目标依据、是否仅为分支和引用 ID。引用可以是 `skill:式神名:技能ID`、`soul:御魂名`、`ai:式神名` 或 `rule:initial_fire`/`rule:fire_cycle`/`rule:speed_priority`/`rule:auto_ai_precedence`。校验器只能查结构与局部算术，不能证明技能语义、完整战斗结算或胜负，因此通过校验后仍需独立审查最关键的推论。
